# Stopped and disconnected terminal lifecycles

Research for [Wheelhouse #88](https://github.com/flotilla-org/wheelhouse/issues/88), 27 September 2026. This document separates the issue's agreed direction, current implementation, and proposed contracts. It does not implement the lifecycle or claim that the proposed APIs exist.

## Scope and evidence

The agreed direction is a retained document after process exit: preserve final output, scrollback, selection/copy and links; show the exit result; disable input and hide the live cursor. Drain final output before releasing execution resources. Give retained presentation memory an explicit budget. Disconnected attachments must not be represented as remotely exited processes. Typing, preview demand and layout restoration must not restart exited commands. [Issue #88](https://github.com/flotilla-org/wheelhouse/issues/88)

Source inspection used Wheelhouse `4ca0dc39ac84ed4153d8f54fda1d6312ff33824c` and Cleat `0cab7cd443c70b40be963abbd80c5b0c17229ff8`. Wheelhouse CI pins a different Cleat revision, `081c566725771ae6bd64fdfc4da82683b85079e8`; the Cleat findings below describe the inspected checkout, not an assertion that every current Cleat capability is already adopted in Wheelhouse. [Build configuration](https://github.com/flotilla-org/wheelhouse/blob/4ca0dc39ac84ed4153d8f54fda1d6312ff33824c/.github/workflows/build.yml#L19)

The central gaps also apply to the pinned revision: its [provider status](https://github.com/flotilla-org/cleat/blob/081c566725771ae6bd64fdfc4da82683b85079e8/crates/cleat/src/provider_ffi.rs#L1444-L1478) reports in-process sessions as STREAMING, and its [exited actor loop](https://github.com/flotilla-org/cleat/blob/081c566725771ae6bd64fdfc4da82683b85079e8/crates/cleat/src/host/actor.rs#L990-L1008) parks the worker.

The exited-actor CPU fix is [Cleat #245](https://github.com/flotilla-org/cleat/issues/245), adopted through [Wheelhouse #78](https://github.com/flotilla-org/wheelhouse/pull/78). Hosting transfer remains separate under [Wheelhouse #81](https://github.com/flotilla-org/wheelhouse/issues/81); remote attachment design remains under [Wheelhouse #21](https://github.com/flotilla-org/wheelhouse/issues/21). Neither moving a live process to another host nor selecting a remote transport is required to define the stopped document.

## What exists today

| Area | Observed behavior and consequence |
| --- | --- |
| Embedded actor after exit | The actor checks child exit, records the result, drains available output and publishes a full change. Once exited it blocks on the command channel instead of monitoring permanent PTY EOF. Commands can still query retained VT state. This removes spontaneous pumping, not the actor thread or runtime. [Pump and actor loop](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/host/actor.rs#L1193-L1336) |
| Execution versus document ownership | `SessionRuntime` owns both a nonoptional `PtyChild` and the VT engine, recorder, held input state and other execution data. There is no split retained-document object in this runtime. Actor destruction sends Stop and joins the worker, with a bounded inline wait and background reaper fallback. [Runtime fields](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/session_runtime.rs#L41-L68), [actor destruction](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/host/actor.rs#L1136-L1165) |
| Final-output drain | The after-exit read removes the live pump byte budget and stops on zero bytes, WouldBlock or accepted PTY EOF errors. It is a drain of currently available output, not a public durable final-content acknowledgment. Exit recording currently precedes that read. Descendants retaining the PTY and final recording order therefore need explicit coverage before strengthening the contract. [Drain implementation](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/session_runtime.rs#L744-L861), [ordering](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/host/actor.rs#L1199-L1223) |
| Daemon-hosted exit | The daemon services output/render work, sees the actor exit mirror, flushes pending delivery, removes the hosted session and closes packet channels. The channel error is a string saying the session exited, not a typed exit result plus final-generation acknowledgment. The daemon therefore does not retain an exited actor indefinitely as the embedded host can. A surviving GUI cell cache is not a retained scrollback document. [Daemon service and removal](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/session.rs#L2184-L2237), [finish](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/session.rs#L2932-L2954), [channel close](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/session.rs#L2307-L2321) |
| Public lifecycle status | The C provider exports transport state. In-process sessions always report STREAMING; daemon states distinguish CONNECTING, STREAMING, DISCONNECTED and CLOSED. The exposed contract does not supply process lifecycle/exit status/final-drain completion. CLOSED is not reliable process-exit evidence: image-channel failure can also close a slot. [C interface](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/include/cleat_provider.h#L526-L555), [failed image channel](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/provider_daemon.rs#L603-L621) |
| Reconnection | The daemon provider reconnects with backoff and reopens existing channel/session identities. It skips permanently closed channels and clears grants and pending transfer state before reopening. This is attachment recovery, not process creation. [Reconnect loop and installation](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/provider_daemon.rs#L529-L588) |
| Wheelhouse input and display | `session_ready` tests pointer availability, not process state. The view sends resize/geometry and input calls through that gate. Mouse selection depends on the last application tracking mode, so a stopped TUI needs an explicit document interaction policy. A daemon status pill exists, but every nonwatching nonstreaming state, including CLOSED, requests another frame. This is a specific host scheduling gap even after the Cleat actor fix. [View initialization/status](https://github.com/flotilla-org/wheelhouse/blob/4ca0dc39ac84ed4153d8f54fda1d6312ff33824c/src/uishell/uishell_views.c#L3240-L3325), [selection/input](https://github.com/flotilla-org/wheelhouse/blob/4ca0dc39ac84ed4153d8f54fda1d6312ff33824c/src/uishell/uishell_views.c#L3388-L3704) |
| View close | Wheelhouse destroys the per-view session handle and releases retained drawing, glyph/cell/image arenas and textures. An embedded view also closes its provider. Shared daemon providers remain open; destroying a daemon session handle closes its attachment channel without killing the remote session. [View cleanup](https://github.com/flotilla-org/wheelhouse/blob/4ca0dc39ac84ed4153d8f54fda1d6312ff33824c/src/uishell/uishell_views.c#L59-L77), [daemon handle Drop](https://github.com/flotilla-org/cleat/blob/0cab7cd443c70b40be963abbd80c5b0c17229ff8/crates/cleat/src/provider_ffi.rs#L678-L690) |
| Restoration and managed content | Initializing a plain embedded view creates its configured command; daemon views persist the session ID and later attach to it. This is insufficient for restoring a stopped embedded document without spawning. Separately, managed content already reconciles intent/target descriptors, leaves held/unavailable/unchanged content alone, and rejects daemon-backed replacement in its first slice. The lifecycle must integrate with those rules rather than redefine an unchanged target as a restart request. ## Proposed state contract

Use separate facts rather than one overloaded "terminal state":

| Dimension | Proposed values | Authority |
| --- | --- | --- |
| Process instance | running; exited with known result; exited with unknown result; unknown | Cleat process owner supplies authoritative evidence, scoped to an instance identity/hosting epoch. Unknown result is distinct from unknown whether it exited. |
| Finalization | active; draining; finalized; finalization failed/incomplete | Cleat owns the output cut, final generation and execution cleanup. |
| Attachment | connecting; connected; disconnected; closed/unavailable, with reason | Cleat provider/transport. Disconnection makes remote liveness unknown; it does not erase a previously confirmed exit for the same instance. |
| Presentation | live; retained document; retained stale content; unavailable; closed | Wheelhouse owns the view and content reference. Cleat supplies document operations and capabilities. |

The names are conceptual, not proposed ABI spellings. A lifecycle notification must include instance identity, exit result availability, finalization status and the final content generation/reference. A transport notification must remain independently queryable. Do not derive either from screen contents, an EOF alone, a missing directory row or a channel-error string.

| Trigger | Transition and required effect |
| --- | --- |
| Explicit launch of a new command | Create a new process instance and live view. Record the instance separately from the command recipe and managed intent. |
| Authoritative process exit | Immediately disable process input; enter draining. Retain output already received and show the exit result with a finishing indication while necessary. Do not yet claim complete final content. |
| Drain and finalization complete | Publish a coherent final generation including cells, scrollback, links and referenced images; establish retained-document ownership; release execution resources; mark the view stopped. Acknowledge/deliver final content before destroying its only authoritative source. |
| Drain fails or output must be bounded | Retain readable content with an explicit incomplete-output/finalization reason. Never relabel partial content as a successful complete drain. Execution shutdown still needs a bounded resolution. |
| Transport loss before confirmed remote exit | Enter disconnected attachment plus stale retained content; remote process state becomes unknown. Disable process input and preserve selection/copy. Reconnection may recover the same instance automatically with bounded backoff. |
| Same instance recovered | Reconcile authoritative process state and content before enabling input. Running returns to live; confirmed exit proceeds through finalization or restores the stopped document. Reconnection must not replay offline keystrokes or create a missing session. |
| Authority reports instance gone without exit evidence | Keep available content and show unavailable/result unknown. Do not invent an exit code or conclude the remote process died. |
| View closes | Release that view's document reference, attachment, callbacks and CPU/GPU caches. Closing an embedded live owner follows existing owned-process teardown; closing a remote attachment detaches only. Explicit remote termination is a separate action. |

An attachment helper exiting locally is evidence about that helper alone. With an SSH/helper transport, show its local result and remote connection loss separately unless the remote authority explicitly reports the remote process result. The remote attachment work in #21 must preserve this distinction regardless of chosen transport.

### Final-output and release boundary

Cleat should own the whole sequence so embedded, daemon and future remote hosts cannot implement incompatible cleanup:

1. Stop accepting process input when authoritative exit is observed. Continue consuming final output and completing required VT parser/render publication work.
2. Define the final-output boundary, including PTY EOF, platform read errors and descendants retaining a writer. Proposed policy: use bounded drain slices and a documented finalization deadline; report incomplete content if the deadline is reached. Do not spin forever on a descendant that continues writing, or silently promise future descendant bytes after finalization. The exact deadline and descendant termination policy remain upstream design choices.
3. Publish/retain the complete document representation and referenced assets under the memory policy. Flush final output to recordings before the terminal exit marker. The current ordering noted above needs verification and, if necessary, correction upstream.
4. Close PTY/process handles, stop exit checks/readiness polling/presentation deadlines, close execution-only recording writers and input state, and retire execution workers. Keep document reads serviceable without recreating a PTY or per-document execution worker.
5. Notify subscribers of the final lifecycle/result and content generation. For daemon attachments, define delivery acknowledgment or a recoverable retained-document reference before destroying the source. Bound slow/disconnected-client retention by the same budget; an undelivered final snapshot must become explicitly unavailable/incomplete rather than retaining execution forever.

This is a proposed contract. Today's embedded actor satisfies passive idle retention but still owns a parked thread and runtime. Destroying it now would also destroy the VT state needed for scrollback; copying only the visible grid in Wheelhouse would not meet the retained-document requirement.

## Stopped document behavior and actions

A stopped view shows a stable "Exited 0", "Exited 7", or "Exited; result unavailable" notice from authoritative data. Signal/termination detail should be preserved when supplied by the shared API. Hide the live cursor and stop its animation; force local selection and scroll handling even when the last application enabled mouse tracking or alternate screen mode. Keep copy, scrollback navigation and link activation working. Preserve referenced terminal images while budget permits. Geometry changes affect document presentation; they must not write PTY resize events. Freeze output-driven animation and scheduling, while allowing user-requested redraws.

Disconnected content remains readable and visibly stale with connection status and last known process information. Cached scrollback/links remain usable to the extent present; do not promise uncached remote data while offline. Closed/unavailable status is stable and must not perpetually request frames. Connection progress should use provider wakes or bounded animation, not a permanent GUI render loop.

| Action | Meaning and permitted effect |
| --- | --- |
| Reconnect | Recover an attachment to the same process/document identity. A missing instance stays unavailable. Automatic transport reconnection is allowed; creating a replacement command is not. |
| Run again | Explicitly launch a new instance from a captured command/cwd/environment recipe. Keep the prior stopped document separately subject to budget; do not mutate its result into "running". If the recipe is missing, require a launch choice rather than substituting a shell. |
| Resolve current managed intent | Ask the existing Andamento/managed-content reconciliation path for the intent's current target. It can select a different instance or report held/unavailable. It is neither retrying the old command nor reconnecting its old identity. Ordinary changes of authoritative target may still drive existing managed reconciliation; mere exit is not a target change. |
| Close | Release the view/reference. Offer remote termination only as a separately named operation. |
| Type, focus, preview, restore layout | Never launch or rerun a stopped command. Process-directed key/paste/mouse/focus events are rejected; document gestures still work. A missing restored document shows unavailable content and explicit actions. |

Restoration needs a saved content kind and process/document identity, distinct from the command recipe. Persist stopped/unavailable identity even if cold content persistence is deferred. Restoring that tombstone may show "retained content unavailable"; it must not fall through to `cleat_session_create`. A first-time explicit launch of a new terminal remains supported.

## Proposed retention budget

The issue requires an explicit budget but does not choose a size. The following is a concrete proposed initial policy, not a ratified default or existing setting:

- Use a configurable **256 MiB process-wide stopped-document budget** with a **64 MiB per-document ceiling**, plus a **64 MiB global derived-cache budget** for those documents. Account for Cleat VT/scrollback/document storage, owned link/image bytes and metadata, and separately Wheelhouse cell/glyph/image CPU caches, textures and retained drawing allocations. Shared storage is charged once; each duplicate cache allocation is charged where owned. Allocation/accounting overhead belongs in the estimate. Values need measurement on real output and image-heavy workloads before implementation is accepted.
- Start accounting while sessions are live, reserve for finalization, and bound incoming final-output allocations; checking only after capturing an unbounded document is insufficient. Charge temporary copies and asset transfers too. Incoming output exceeding the per-document ceiling retains the newest bounded content and an explicit "older output omitted" notice, preserving the final visible output and exit result; an oversized image may be replaced by a labeled placeholder. Never silently discard content or misreport a complete original history.
- Evict reconstructible GPU/draw/glyph caches first. If owned content still exceeds the cap, evict the least recently interacted-with, nonvisible stopped document's payload, leaving identity/result metadata and a visible content-unavailable marker. Visible documents are protected from whole-document eviction; when all candidates are visible, apply the disclosed per-document truncation/asset omission rule until the global cap is met. A displayed truncation marker must survive restoration metadata. Reserve and account for bounded identity/result metadata too; if even the minimum readable content and metadata cannot fit, reject further retention admission with a visible limit notice rather than claiming an unlimited number of protected views. Selecting a document whose payload was evicted never starts its command.
- Closing the last view releases its references and derived caches promptly. A separate document owner may retain payload only within the global budget; explicit close can discard it. Daemon-side retained storage needs its own documented budget/expiry and reference semantics; client budgets cannot bound server retention. Provider connections shared with other live views are not charged as per-document execution resources and need not close when one stopped view closes.

Cold unloading to disk and rehydration can follow later. This policy bounds memory without making cold storage a prerequisite, but payload eviction/truncation changes what remains readable and must be visible to the user. Before shipping, decide whether users need a pin/export affordance and what happens when pinned data exceeds the cap; no unlimited exemption should be implicit.

## Shared Cleat API work before host implementation

Track this shared contract in [Cleat #277](https://github.com/flotilla-org/cleat/issues/277) before introducing host-specific substitutes.

The remaining work belongs at the provider boundary, not in Wheelhouse PID polling, `/proc` inspection, terminal escape parsing or channel-error string matching:

1. Export authoritative process lifecycle, known/unknown exit result, finalization status and stable instance identity independently of connection state. Notify with the existing edge-triggered wake discipline and define race-safe reads with render generations.
2. Split execution finalization from retained terminal/document ownership. Supply retained scrollback, selection/copy data, links and assets after PTY/worker retirement, including document-only resizing if supported. Expose relevant capabilities and memory accounting so the host can enforce a budget without guessing internal ownership.
3. Define daemon final document delivery/ownership and typed closure reasons. An exit, disappearance, protocol/asset failure and connection loss must be distinguishable. Preserve enough final state/result for a reconnect after exit within retention limits, or explicitly report expiration/incompleteness.
4. Gate all process-directed input and execution resize/focus operations after exit and while disconnected; maintain document-only viewport/read operations. Reject without silently starting a command or queuing input for later replay.
5. Specify and test cross-platform final drain/recording order, bounded finalization, descendant-writer handling, worker retirement and cancellation-safe close during drain.

Wheelhouse can then implement status/actions, document cursor/input policy, stopped restoration metadata, scheduling changes and cache budgeting on the shared contract. The existing CPU fix remains useful while that API work proceeds, but it must not be described as complete resource release. Hosting transfer (#81) remains independent.

## Verification contract

These are proposed acceptance checks, not test results from this research pass. Prefer shared provider behavior tests plus narrow Wheelhouse interaction/diagnostic tests; platform PTY cleanup needs real integration coverage.

| Check | Evidence required |
| --- | --- |
| No spontaneous execution after finalization | Instrument pump/readiness calls, process checks, presentation deadlines and execution-worker count. After finalization and a settled interval with no input, counters stop, per-session execution workers end and PTY/process handles return to baseline while the document remains open. Measure GUI frame requests separately; a CLOSED pill must not loop. Shared daemon transport work for other live sessions is allowed. |
| Final content/readability | Print a unique final suffix larger than one live pump slice, split UTF-8, styled text, links and images; exit with a nonzero result. Verify suffix, code, scrollback, selection/copy and links after finalization and worker retirement. Cover alternate-screen/mouse-reporting state and geometry changes; cursor remains hidden. Check recording output precedes its final exit marker. |
| Drain edge cases | Exercise EOF, Windows/Unix EOF error handling, descendant writer continuing after leader exit, drain errors, slow readers and close during finalization. No infinite spin, no indefinite execution-resource retention, and any truncation/incomplete final output is reported. |
| Disconnect without exit | Break the attachment transport while the remote command keeps producing output. Retain stale content, show disconnected/unknown remote state, reject process input, and record no exit or replacement launch. Restore transport and confirm same identity and correct content/grant recovery. |
| Exit during disconnection | Exit the remote process while offline. Recover its authoritative exit and final document if retained; if unavailable, show unknown result/expired content without inventing success or recreating the command. Test channel/protocol failure separately from actual process exit. |
| No implicit restart | Count process creation across typing/paste, focus, preview demand, workspace switching, layout restore and unchanged managed reconciliation after exit. Count stays unchanged. Explicit Run again creates exactly one new identity; Reconnect creates none; managed resolution follows the current authoritative target and respects held/unavailable. |
| Ownership and close | Close one of two attachments; the other remains usable and the daemon process survives. Close embedded live/stopped views and close during drain; owned resources and callbacks eventually release without stale-pointer wakes. Shared providers remain valid for other views. |
| Memory cap | Retain many stopped terminals and image-heavy content, including visible-only workloads and multiple views of one document. Measured owned CPU/GPU allocations stay within the proposed accounted caps/reservations; truncation/eviction is visible, exit metadata survives, and restore/access never launches a replacement. |

The existing Cleat regression checks that an exited actor stops engine polling, can still answer requests and drops its engine on actor close. It does **not** establish PTY release or worker retirement with a retained document. Its final-text assertions require `ghostty-vt`. Retain that test and extend the lifecycle contract rather than treating its success as all the checks above.
